# Webapp: Pipeline Control Panel & Visualization Dashboard — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local FastAPI + no-build vanilla-JS single-page webapp that visualizes the pipeline (overview, benchmark/gate, data quality, datasets/golden, training curves, triage) and lets the operator trigger stages, triage samples, and review deployments from the browser.

**Architecture:** New `src/frigate_learn/webapp/` package: a FastAPI app factory, a read-side `queries.py`, an image `serving.py`, and a background `jobs.py` job manager that runs existing pipeline stage functions in a daemon thread. The webapp reuses the library directly (no subprocess-to-CLI). A no-build vanilla JS SPA in `static/` is served as static files. New CLI command `frigate-learn web`.

**Tech Stack:** Python 3.11+, FastAPI + Uvicorn (new `web` extra), SQLAlchemy, SQLite, Pillow (existing), vanilla JS + vendored uPlot, pytest + FastAPI TestClient.

## Global Constraints

- Only new runtime deps: `fastapi>=0.110`, `uvicorn>=0.29` (new `web` extra).
- Single-user localhost: bind `127.0.0.1`, no auth, no CORS. Never read `.env`/VLM key.
- One uvicorn worker; pipeline stages run in a daemon thread via `run_pipeline`.
- Reuse existing library: `run_pipeline`, `Triage.set_sample_quality`, `record_deployment`, `results_from_json`, `pareto_frontier`, `GoldenDataset`, `read_yolo_label`, `Sample/Annotation/Job/Deployment/CollectionFailure` models.
- Reads go through `Database.session()`; no schema changes, no new migrations.
- Artifacts (`benchmark-results.json`, `build.json`, `results.csv`, `golden/`) read in place; never cached.
- Overlay boxes are normalized (0–1); the browser scales them.
- All 202 existing tests stay green. Tests never hit Frigate/torch/VLM.
- No comments in code.
- Vendored uPlot file must be committed (license header kept).

## Task 2 — Read-side queries (`queries.py`)

**Scope:** Pure functions that read the DB and artifact files. No HTTP. Each returns plain dicts. All paths resolved through `AppConfig` and existing helpers (`results_from_json`, `GoldenDataset.load`, `read_yolo_label`, `next_build_version`).

**Functions (`queries.py`):**
```python
def overview(config, db) -> dict
def benchmark(config) -> dict
def deployments(db) -> dict
def quality_counts(db) -> dict
def datasets(config) -> dict
def training_index(config) -> dict
def training_run(config, run) -> dict | None
def samples(db, *, status=None, quality=None, camera=None, verified=None, limit=50, offset=0) -> dict
def sample_detail(db, sample_id) -> dict | None
```

**Behavior:**
- `overview`: `{"steps": PIPELINE list, "auto_enable": cfg.automation.enable, "samples": {total, verified, unverified, quality_*}, "cameras": sorted list, "vlm_enabled": bool, "disk_free_bytes": shutil.disk_usage(config.base_dir)[2], "next_build_version": run.next_build_version(config), "pipeline": [recent Job rows]}`.
- `benchmark`: read `config.resolve(config.data.root, "benchmark-results.json")` via `results_from_json` (missing file → `{"results": []}`). Return `{"golden": cfg.evaluation.golden_dataset, "baseline": cfg.deployment.baseline, "max_latency_ms": ..., "results": [r.to_dict() for r in results], "pareto": pareto_frontier(results)}` plus `results_updated_at` mtime.
- `deployments`: all `Deployment` rows ordered by `created_at desc`, each with parsed `metrics_json`, `reasons_json`, `verdict`, `deployed`, `deployed_at`.
- `quality_counts`: `{"total", "verified", "unverified", "by_quality": {useful|bad|duplicate|ignore: count}, "one_class_boxes": sample count with ≥1 verified annotation, "problematic": count where quality in (bad,duplicate)}`. Per-class `verified` box counts from `Annotation` (verified=1), keyed by label.
- `datasets`: list `vNNN` dirs sorted desc; for each read `build.json`: `{version, built_at, images_written, total, verified, skipped_class, split_counts, classes}`. Missing build.json → `{"version": name, "error": "build.json missing"}`. Golden segment: `"golden": {"version": cfg.evaluation.golden_dataset, "exists": bool, "classes": [...], "image_count": N, "per_class": {label: count}}` (counts via `read_yolo_label(label_path, num_classes=...)`; wrap each file read in try/except). Golden dataset path = `config.golden_dir() / cfg.evaluation.golden_dataset`.
- `training_index`: list run dirs under `config.resolve(config.data.root, "training")` (only dirs containing `results.csv`), sorted desc: `{run: name, model, tag, dataset, results_mtime, latest_map50, best_map50, has_weights}`. Parse CSV with `csv.DictReader` (missing `metrics/mAP50(B)` → map50=None). `has_weights` = `run_dir/weights/best.pt` exists. Guard num_classes when reading yolo lines (`max(1, len(classes))`).
- `training_run`: parse `results.csv` → `{run, columns, rows: [dicts], best_map50, latest_map50, epochs: count, weights_exists, dataset}`. rows are dicts cast to float where possible, else str.
- `samples`: filter by exact match on `status`, `quality`, `camera`, `verified`; order `timestamp desc`; limit clamp 1..200; return `{total, limit, offset, samples: [{id, camera, timestamp, label, score, quality, status, verified, has_image, has_annotations}]}`. `has_image` = `image_path` non-null and file exists; `has_annotations` via subquery count.
- `sample_detail`: `{sample: {...same}, "annotations": [{source,label,box:[x1,y1,x2,y2],confidence,verified}], "frigate": {label,score,box:[...]} | None, "image_url": "/images/<id>", "thumb_url": "/images/<id>/thumb"}`. Image URLs only when `has_image`.

**Tests (Task 2):** seed a tmp dir via `build_config({"data": {"root": "data"}}, tmp_path)`; write a fake `images`/`golden`/`datasets`/`training` tree + a `benchmark-results.json` fixture (2 candidates), insert Sample/Annotation/Deployment rows via `db.session()`, then assert each query's shape and a few exact values. ## Task 3 — Image serving (`serving.py`)

**Scope:** Serve originals and lazily-built thumbnails for sample images, with a path-traversal guard. Reuse the PIL pattern from `inspect/report.py._thumb`.

**API (functions, not routes):**
```python
THUMB_MAX_WIDTH = 480

def resolve_image(config, db, sample_id) -> Path | None        # original path or None
def resolve_thumb(config, db, sample_id) -> Path | None        # generate lazily into previews_dir()/thumbs/<id>.jpg
```
`resolve_image`: load `Sample.image_path`; if absent return None; `p = Path(path).resolve()`; allow only if `p.is_relative_to(config.images_dir().resolve())` OR `p.is_relative_to(config.resolve(config.data.root).resolve())`; reject otherwise (guard). Return `p` if `is_file()` else None. (`Path.is_relative_to` requires Python 3.9+; project is 3.11+.)

`resolve_thumb`: thumb lives at `config.previews_dir() / "thumbs" / f"{sample_id}.jpg"`; if missing and original exists, build a width-≤480 JPEG (quality 82, `Image.Resampling.LANCZOS`, convert RGB) into that dir (mkdir parents), swallow conversion errors → return None if build fails. Never return a thumb fetched from the store.

**Tests:** image present → served bytes equal file bytes; missing sample → None; traversal path stored in DB (`/etc/passwd`) → None; thumb builds once and is a JPEG (`\xff\xd8` magic); second call returns cached file; thumb dir created under `previews`.

## Task 4 — Background job runner (`jobs.py`)

**Scope:** A `JobManager` that runs pipeline stages in a daemon thread, records progress in the `jobs` table, captures the `frigate_learn` logger for a bounded log tail, and recovers stale jobs on startup. One concurrent job at a time.

```python
class JobRunningError(Exception): ...

class JobManager:
    def __init__(self, config, db): ...
    def mark_stale_running(self) -> None          # called at construction
    def start(self, steps: list[str], *, dry_run: bool = False) -> str  # raises JobRunningError if busy
    def current_job_id(self) -> str | None        # id of running job in memory, else DB-scan
    def get(self, job_id: str) -> dict | None     # {id, type, status, started_at, finished_at, error, reports, log_tail}
    def recent(self, limit: int = 20) -> list[dict]
```

**Behavior:**
- Construction: `db.migrate()` (idempotent), then `mark_stale_running()` → UPDATE `jobs SET status='failed', error='terminated by server restart' WHERE status='running'`.
- `start`: reject if `not steps` or any step not in `run.PIPELINE` (raise `ValueError`); if `self._thread and self._thread.is_alive()` or a DB scan finds `status == "running"` → raise `JobRunningError`. Else generate `job_id = uuid4().hex[:12]`, insert `Job(id, type="pipeline", status="running", started_at=utcnow())`, spawn `Thread(target=self._run, args=(job_id, steps, dry_run), daemon=True)`, `.start()`, return id.
- `_run(job_id, steps, dry_run)`: attach a `logging.Handler` to `logging.getLogger("frigate_learn")` (not `configure_logging()`; it resets all handlers) that appends formatted lines to a thread-local list capped at 200; call `run_pipeline(config, db, steps=steps, dry_run=dry_run)` inside try/except; on completion build reports as `[{"name","status","message"}]`, mark `status = "failed" if any(r.status=="failed") else "finished"`, `error` = first failed message or None, `finished_at = utcnow()`, `metadata_json = json.dumps({"steps": steps, "dry_run": dry_run, "reports": reports, "log_tail": tail})`. Remove the handler in a `finally`.
- `get`: read Job row; parse metadata_json; return dict incl. `reports` and `log_tail` (both `[]` when absent). `recent`: latest N by `started_at` desc, same parse (log_tail truncated to last 50 lines).

**Tests:** because real steps touch Frigate/torch/VLM, monkeypatch `webapp.jobs.run_pipeline` (module attribute `run_pipeline`) with a stub returning a fixed `StepReport` list, driven by a mutable box: a stub that (a) blocks on an `Event`, (b) calls `logutil.info("hello-job")`, (c) returns reports. Cases: `steps=[]` and `steps=["bogus"]` → `ValueError`; busy → `JobRunningError`; stale `running` row flipped to failed on construction; log tail contains the stub's log line; `get`/`recent` shapes; finished status when reports all executed, failed status when a report is failed.

**Verify & commit:** Task 4 tests + webapp file green; suite green. Commit `webapp: add background job manager`.

|---|---|---|
| GET | `/api/health` | `{"status": "ok"}` |
| GET | `/api/overview` | `queries.overview` |
| GET | `/api/benchmark` | `queries.benchmark` |
| GET | `/api/deployments` | `queries.deployments` |
| GET | `/api/quality` | `queries.quality_counts` |
| GET | `/api/datasets` | `queries.datasets` |

| GET | `/api/samples/{sample_id}` | `queries.sample_detail` or 404 |
